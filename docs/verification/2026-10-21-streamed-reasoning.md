# Streamed reasoning — 2026-10-21

The shared projection now consumes Codex summary-part, summary-text and raw-text
notifications. Before this change an empty started reasoning item stayed hidden
while its turn was working, even though the Host had received its text.

The [receipt](assets/streamed-reasoning/receipt.json) binds source/binary hashes,
schema, tests, clipboard readback and screenshots. Private task evidence is in
`/tmp/fleetpane-reasoning-20261021`. All supplied content is synthetic.

## Local checks

Two new `cargo test -p fleetpane-session --locked reasoning::tests` regressions
first failed: the summary-part event was ignored, and invalid known notifications
were silently ignored. The completed implementation passes 229 workspace tests
and 20 desktop tests. Coverage includes independent summary/content indices,
exact Unicode/whitespace, empty slots, repeated part markers, final replacement,
wrong/missing identities, negative/huge indices, malformed arrays and the 2 MiB
budget. A separate history regression covers already-snapshotted events and
later updates during earlier-page loading. The native row regression checks that
only the reasoning card is introduced/updated and its Copy fields remain exact.

Both root and desktop formatter, strict all-target Clippy, build and
`git diff --check` pass. Fifteen Python tests and the existing `session-smoke.py`,
`history-smoke.py` and `acp-order-smoke.py` pass. These checks do not call a model.
Protocol field names/types were checked against JSON schema generated by the
installed Codex CLI 0.163.0; its three notification schemas are retained.

## Native before and after

The hidden Linux workspace uses a 1400 × 1000 display. The old 1100 × 720 app
starts a gated reasoning turn and shows only the user message and working state.
The Host records the reasoning delta; [before](assets/streamed-reasoning/before-sent.png)
has no reasoning card. Closing that app normally exits zero without stopping the
owned Host/provider or resolving a separate session's pending approval.

The fixed app opens the same running thread and shows its initial summary.
Advancing the provider gate updates the expanded card with more summary text,
a second part and raw content without Reload. Follow-tail scrolling keeps the
new text reachable. Copy returns the exact 141-byte JSON fields, including
Chinese, literal Markdown markers, line breaks and leading/trailing spaces.
After normal completion and Reload conversation, the copy is identical and the
card appears once. A 29-byte multiline draft also copies back exactly.

A second native send starts from an empty reasoning item. Its initial text
appears while working, then all parts update in the same expanded card
([before advancement](assets/streamed-reasoning/second-live-first.png),
[after advancement](assets/streamed-reasoning/second-live-update.png)).
The copied fields equal the earlier 141-byte payload. Native Stop ends precisely
that turn as interrupted; the other session's approval remains pending and its
turn stays active. The original Host ID and provider PID are unchanged.

The fixed app closes through its titlebar and exits zero. The owned Host/provider
then stop explicitly, its socket disappears, and the hidden workspace stops.
The user desktop and live providers are not touched.

## Limits

This accepts the shared decoder/history projection and covered Linux native
synthetic workflow. It does not establish external OpenCodex/DeepSeek model
reasoning behavior, macOS/Windows native rendering, IME/accessibility or
performance. Reasoning details remain literal text. No new item-level activity
status is inferred. Existing 500-item/turn and 2 MiB conversation limits remain.
Remote CI is a separate result after publication.
