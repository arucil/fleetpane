## Behavior and regression

`session SOCKET wait THREAD TURN [--timeout-ms N]` observes the exact turn and
returns a structured finished, unknown, attention or timed_out report. It preserves
failure/refusal/cancellation and does not infer task success from settlement.
It uses an existing lease for initial queries and does not claim control.

Review found that a delayed query can return stale inProgress **after** the
completion event was published. Using the reply's sequence as the starting cursor
misses that event. The new regression failed before the fix with `TimedOut`, then
passes after capturing a snapshot cursor before history lookup. The Host code
stamps query replies at arrival (`State::record_from`, Unix query delivery); it
supplies no independent provider snapshot version. This fix changes wait's cursor,
not the Host/provider protocol. Six targeted tests also cover metadata/status,
exact request binding, older-page lookup, partial event-page draining during
controller replacement, missing/repeating cursors and a stalled initial read.

## Owned process acceptance

`python3 scripts/wait-smoke.py --real-codex --evidence-dir PRIVATE_DIRECTORY`
passes with the final binary. All inputs, endpoints and sessions are synthetic:

- Codex protocol fixture: completed, failed and interrupted turns; repeat reads
  and older target lookup; question attention; unrelated question cannot end a
  held turn's wait; missing target, invalid deadline, no owner and take-control
  refusal. Owner, provider PID, journal identities/count, pending requests and
  activity remain unchanged by isolated waits. Query replies may advance sequence.
- SIGINT kills only the observer; the held turn and independent question remain.
  Another wait survives an explicit controller replacement and Stop, reports the
  exact interrupted turn, and leaves the other question pending. Provider loss
  returns an error rather than a completed report.
- ACP fixture: explicit refusal reason; target-only permission attention with a
  separate session's approval retained; explicit Stop targets one session. Killing
  the owned Host group while waiting yields an error. Restart preserves the
  unfinished turn as unknown; a separate controller claim permits a read-only
  unknown report without context resume, prompt replay or new mutation receipt.
- Installed Codex app-server with private CODEX_HOME and one gated loopback SSE
  response: timeout while its model request waits, followed by actual completion
  after releasing the gate. Exactly one model request, same Host/provider PIDs,
  same controller and mutation journal before/after. This establishes protocol
  compatibility, not an external model/tool result. No account state is changed.

All observer processes terminate. Every owned Host exits, including the deliberate
ACP kill/restart; provider PIDs are gone or zombie. No shared Paseo/Codex/DSH
process, user's workspace, native display or hosted service is used.

runtime, hosted CI, release, public MCP API or performance gain is claimed.
Wait's finite deadline starts after CLI discovery; expired event cursors and
incarnation/lookup conflicts are explicit errors. The command observes the
existing protocol and cannot prove a user task finished correctly.
