# ACP tool snapshots and native details

Verified locally on 2026-10-21 with uncommitted work on
`feat/session-host-foundation`. [ADR 0035](../adr/0035-acp-tool-snapshots.md) defines
the behavior. The [receipt](assets/acp-tools/receipt.json) binds code/binary hashes,
automated logs, clipboard readbacks, native screenshots and scoped Paseo review
through ordinal 71; earlier receipts retain their own snapshots.

## Reproduction and implementation

Two regressions failed before the change: a legal empty title was rejected, and
malformed updates were accepted rather than rejected atomically. The new process
scenario also failed against the previous built Host on an initial call with a
nonempty title and omitted status: `ACP status must contain a string`.

The corrected runtime defaults a new call to pending/other with empty collections,
validates known fields before mutation, and replaces non-null supplied values.
Updates retain omitted/null fields. Raw input/output are arbitrary JSON, including
false and zero; objects are replaced rather than merged. Collections can be
cleared with empty arrays. Empty titles display a name without changing stored
or copied source data. Optional metadata remains backward compatible with older
archived tool snapshots.

## Native acceptance

Used hidden Linux workspace `fleetpane-acp-tools-20261021` and private fixture
Host/provider processes. Gated fixture updates advance only when the prior view
has been inspected. The final QA uses `/tmp/fleetpane-acp-tools-qa-final`; an earlier
pending-only preview was closed before the final lint-adjusted build.

- The minimal initial call rendered pending. Expanded details showed read_file,
  other kind, the exact file path/line 0 and false input.
- In-progress and completed reports updated the same expanded card. Kind changed
  to read, location to line 42, input/output were replaced, and an empty title
  displayed read_file. Native copy retained the empty title and exact fields.
- Empty content and locations removed earlier detail text/path while preserving
  the card expansion and zero output. A second failed tool rendered false output;
  both snapshots were copied and checked independently.
- Normal close exited 0 while the private Host remained alive. Restarted that
  Host and reopened the archive: exact three item IDs and snapshots survived,
  with no prompt replay. Native archive details/copy and Reload conversation were
  checked; explicit Resume context remained available and Send disabled. The
  second normal close exited 0.

Tool content remains plain source text in details. File locations are display
metadata; follow-along navigation, embedded provider terminals, richer tool diff
rendering and full media interaction are not completed by this slice. It does
not establish real DSH/OpenCodex metadata behavior or performance parity.

Both final UI stderr logs contain only the hidden X server's Mesa DRI3 warning.
All nine task-owned preview/final/archive process IDs are absent and the hidden
workspace is stopped. No shared user provider or desktop was restarted.
