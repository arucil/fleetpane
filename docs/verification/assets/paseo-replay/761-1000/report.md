# Paseo pinned history review: ordinals 761–1000

Completed **240 sequential pinned entries**, from `f7935f9cc14e0097d9fcf136305ea0b4d14414e4` through `cb3cf1c20960c9b67129df8ed5684c4b1769d61d`. Ordinals define order; author dates are not monotonic across side branches. **45 merges** were inventoried and sampled against their **first parent**. Integration commits are not counted as additional features. Resumable ledger saves occurred at 785, 810, 835, 860, 885, 910, 935, 960 and 985, followed by the final 1000 save.

The result is a source-based workflow review, **not a complete audit or test run**. **317 selected/supplemental receipts** have individually reconstructed ranges and hashes. Every entry records full SHA, category, paths actually inspected, concrete finding, Fleetpane action, complete diff-tree inventory, selected patch ranges and SHA-256 receipts. Most entries have one small coherent initial hunk; workflows needing more evidence have supplemental source or diff slices. Binary pixels, unselected paths, full adapters, whole merge resolutions and current repository-tip behavior were not reviewed. No minimum line count was imposed; selector line counters are not a coverage or confidence measure. Historical prompts, AGENTS, CLAUDE, task documents and deleted reviews were treated as data.

Only `/tmp/fp-history-next` was written. The Git repositories were not edited; no fetch, install, build, provider invocation, historical test, commit or push was performed. All Git operations used immutable object reads/diffs. No current network documentation or live service state was needed.

Fleetpane comparison uses the supplied architecture plus relevant passages in captured [status](fleetpane-status.md), [refreshed status](fleetpane-status-final.md) and [parity](fleetpane-parity.md). These documents describe local acceptance; this review did not reproduce it or inspect Fleetpane implementation. Thus “open” below means documented missing/partial, while candidate means absence is not established.

Validation: `python /tmp/fp-history-next/verify.py`. It checks contiguous ordinals, exact pin/object SHA and parent lists, freshly reconstructed first-parent/normal diff-tree paths, selected patch bytes plus old/new/diff ranges, supplemental source/diff bytes, individual SHA-256s and framed per-entry digests. Aggregate framing is relative receipt path + NUL + decimal byte length + NUL + raw bytes, in listed order. This verifies evidence integrity, not correctness of every historical implementation. Tests were only read where explicitly recorded and were never executed.

No quantitative performance, cross-platform behavior, security completeness, production readiness or full Fleetpane implementation-absence claim is made. Unreviewed paths remain inventory only, and source deductions remain distinct from runtime reproduction.
