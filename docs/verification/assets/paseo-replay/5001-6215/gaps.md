# Concrete source-derived workflow gaps

These are candidates relative to the captured Fleetpane status/parity documents, not reproduced Fleetpane defects or runtime acceptance. Rust GPUI Kit and stable Session Hosts remain the target. OpenCodex and DeepSeek take priority; Kimi/GLM are excluded and Git Diff expansion is deferred.

1. **Recoverable workspace archive/restore and explicit deletion.** Ordinal 6051 source receipts cover ownership and index-lock checks, before/after HEAD/index identity, checksummed chunks, fsync/atomic manifest publication, detached-HEAD retention, branch movement/checkout refusal, and restore-token fencing before discarding the sole archive. Its archive caller stops workspace agents/terminals and rechecks references before removal. Ordinal 6053 durably claims an exclusive owned worktree deletion, refuses cold storage, stops setup/terminals/agents, then checks exclusivity again. Fleetpane documents worktree removal/archive and interrupted-operation recovery as open. A branch-only recreation would not preserve staged/dirty/untracked content or runtime resource ownership.

2. **DeepSeek private-history continuation with explicit completeness limits.** Ordinals 5488/5489 resolve exact cwd/session log paths and replay decoded JSONL as ACP updates. Supplemental 5488 reads walk concatenated Zstandard frames, cap decoded bytes at 256 MiB, tolerate a torn trailing frame after prior complete frames, and translate records. The JSONL parser actually skips every invalid line, wider than its torn-final-line comment; do not copy that policy as proof of complete history. Fleetpane already has offline DSH v3/v4 snapshots and Host-observed archive evidence; private provider replay and paginated continuation remain distinct gaps, not reasons to rebuild import.

3. **Stable-cursor discovery and windowed history.** Ordinal 5527 pages updated-at Codex threads, deduplicates IDs, bounds the requested window, refuses no-progress cursors, and filters only actual supplied cwd. Ordinals 6007/6194 use immutable creation order for full directory scans with 200-row pages. Ordinals 5043/5081/6126 preserve target item/window and remove cached prefixes only with matching epoch/sequence during catch-up. Fleetpane loaded-row sorting and bounded search are already locally documented; full-index discovery, history eviction and scroll restoration remain open.

4. **Precreation draft handoff and queue ownership.** Ordinal 5409 compares text version, setup identity and attachment identity before clearing any draft state. Its background creation path is deliberately isolated from a tab-triggered submit to avoid a second create. Ordinal 5101 rejects a pending run cancelled before provider turn admission. Fleetpane's durable creation intents and session drafts already exist; options/media/precreation drafts and cross-provider queue lifecycle remain open. Keep Fleetpane's durable single-dispatch receipt model rather than copying the historical non-deduplicated create API.

5. **Authenticated destination routing and cross-Host orchestration.** Ordinal 6206 supplemental logic retains non-ENOENT registry errors, strips connection secrets from public lists, binds routed hello to origin/scope/permissions, and refuses data until destination identity is verified. Remote tool operations reject a caller locked to local cwd, resolve the destination workspace, and carry a Host-qualified parent address. The separate extra commit documents `{serverId, agentId}`, destination-owned paths/workspace IDs, registration IDs and per-tool remote scope. Fleetpane's named local Hosts and exact source opening are already documented; authenticated registry/transport, durable routing and cross-Host completion/permission notifications remain open. This is routing to existing runtimes, not process migration.

6. **Account/usage diagnosis and explicit recovery.** Ordinal 5377 selects only current quota-limited targets, deduplicates Host/agent, rechecks idle/no-pending-permission/online state and records sent/skipped/failed results for explicit Continue. Ordinal 5818 starts account probes in one deadline window and retains per-login errors; ordinal 5770 invalidates account mappings when sources change. Ordinal 5520 classifies provider-exhausted 429/disconnect as transient, while AgentManager schedules automatic continuation in 5388/5517. Classification does not prove replay safety; Fleetpane should retain unknown-outcome refusal and explicit user action. Provider setup, usage source identity and profiles/defaults remain open.

7. **Extension and provider event lifetimes.** Ordinal 5155 refuses replacing a session host with running plugins and waits both child close and session close. Ordinal 5473 refuses unknown/offline Hosts and aborts cached client lifetime on replacement; 5465 reattaches only eligible hello frames once. Ordinal 5362 handles vendor notifications synchronously in wire order; 6152 buffers interactive startup events until a subscriber exists. Ordinal 6131 refuses steering without negotiated capability. Fleetpane's remaining plugin, provider recovery and resource-complete Host retirement work needs these ownership/ordering invariants; no plugin implementation or blanket ACP steering support is claimed.

Additional candidates: terminal word/wide-cell selection (6125/6127/6162), file/terminal Find, conflict-aware editing, initial attachments, model profiles and font/layout preferences. Existing native functionality should be checked against status/parity before any implementation.

All supporting source excerpts, full SHAs, paths, parent bases and exact hashes are in review.json and receipts/. The extra commit has no pinned ordinal and has separate review/validation receipts. No product edit, application build/test, historical instruction execution, live session or full-audit claim is made.
