# ACP anonymous stream chronology

Verified locally on 2026-10-21 (Asia/Shanghai), with uncommitted work on
`feat/session-host-foundation`. [ADR 0033](../adr/0033-acp-anonymous-stream-boundaries.md)
defines message identity and anonymous segmentation. The [receipt](assets/acp-order/receipt.json)
binds this evidence to source/binary hashes and the scoped Paseo review through
ordinal 54. Earlier appearance/archive/stop receipts retain their own snapshots.

## Reproduction and fix

Two new adapter regressions failed before the fix:

- Anonymous text before and after a tool/thought collapsed into earlier rows.
  Expected seven ordered items in the unit fixture; the old adapter returned four.
- Explicit messageId `stream` and unidentified text shared the same internal ID.

`python3 scripts/acp-order-smoke.py` also failed against the previous compiled
Host with the new deterministic `[chronology]` fixture. This independently proves
the observed projection problem, rather than treating an upstream title as a bug.

The fix separates explicit message IDs from anonymous segment IDs, and combines
anonymous chunks only within the same adjacent role/stream. Tool updates patch
their existing card but end the anonymous segment. Explicit IDs continue to
identify one message across interleaving. No text is trimmed; no historical
merged record is rewritten or prompt replayed.

## Native acceptance

The final native binary ran in the private `fleetpane-acp-order` hidden X11
workspace against owned ACP fixture processes. The actual window showed:

- Before-text → first tool → after-text → thought → subsequent text segments;
  explicit message `one two` stayed a single item and anonymous final text stayed
  distinct. First/last portions are captured separately in screenshots 01–02.
- Expanding the first tool showed its original completed result, not a new or
  displaced tool row. Copy returned its complete structured content. Screenshots
  03–04 and clipboard readback record this.
- Copying the first text returned exactly `Before 中文\n  keep spaces `, including
  the newline, two leading spaces on line two and trailing space. The final text
  copied exactly as `Anonymous final 中文`.
- A multiline draft was saved without sending. Normal window close exited **0**.
  The private Host/provider were then stopped and restarted. Shared reads showed
  an archived session with exactly the same full turn/items and IDs.
- The replacement native window displayed the archive, first/last ordering and
  correct copies; Reload preserved the archived content. **Resume context** and
  disabled Send made runtime state explicit. It was not resumed. Screenshots
  05–07 and post-restart clipboard readback record this.

The fixture prompt file still contained exactly one `[chronology]` prompt after
both native windows and the Host restart. The old Host-incarnation draft remains
stored under its original identity; it is not automatically moved to a new
incarnation or sent. Both desktop exits were **0**, their stderr logs were empty,
and all owned native/Host/provider processes and the hidden workspace were stopped.

## Limits

No real DSH/OpenCodex turn, provider transcript import, new elicitation support,
legacy modes-only support, full raw event log, older-history reconstruction,
macOS/Windows native acceptance, or performance improvement is claimed here.
Same-ID provider chunks intentionally patch the same message; the interface is
a structured conversation rather than a verbatim chronological event log.
