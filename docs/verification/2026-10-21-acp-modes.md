## Reproduction and implementation

The pre-fix adapter regression receives modes in a successful session/new reply
but finds null in the returned thread. Its failing log is retained. The adapter
now preserves typed modes on new/resume, handles current_mode_update as metadata
outside the active-prompt requirement, and implements session/set_mode for an
advertised choice. Existing configOptions are unchanged. See [ADR0039](../adr/0039-acp-v1-session-modes.md)
for the official v1 contract and the separate v2 boundary.

Mode/config commands serialize per session. A mode change can run during a
prompt or permission wait; other sessions and Stop remain usable. The current
mode changes only on confirmed ACK/notification. A newer provider notification
survives a late ACK, errors keep confirmed state, and an unknown provider-selected
current ID is displayed exactly without inventing a selectable choice. Modes
are committed with session metadata before publication. Archives remain read-only
until explicit resume replaces the old catalog, including its absence.

## Native Linux acceptance

A task-owned hidden 1680×1100 X11 workspace ran three desktop windows sequentially,
two incarnations of one private Host/provider and two synthetic sessions; no real models were called.

- The selector shows Ask/Code/Restricted with provider descriptions. Selecting
  Code changes only the selected session; model/reasoning controls remain intact.
- Restricted returns a visible synthetic provider rejection, leaving Mode: Code.
  A native clipboard readback preserves `Mode QA draft 中文\n  keep indentation`
  exactly; the earlier type-text helper did not preserve Unicode/newlines, so the
  verified input used clipboard paste.
- The native Send button sends `[permission]` once. During that pending request,
  the mode menu stays enabled while model/reasoning are disabled. Choosing Ask
  keeps the same turn, request ID, history, Host ID and provider PID; the second
  session stays Ask with no history.
- A provider current_mode_update selects `provider-only`. Readbacks show identical
  conversation items and permission request. Replacing the desktop window retains
  the same Host/provider, pending request, exact mode and saved draft. Native
  clipboard readback is exactly `Pending mode draft 中文\n  retain spaces`.
- Native Stop settles the turn as interrupted, clears its permission, preserves
  the current mode and produces no second prompt. The second session remains Ask.
- A final run records binary hashes before launch. After Host restart, the native
  archived view shows Mode: provider-only disabled. Resume context replaces it
  with Fresh mode and a one-choice menu; old choices disappear. Exact history is
  retained, the second session remains archived, and no prompt is replayed.

Saved PNGs were inspected with file OCR as needed; immediate input screenshots may
precede async rendering and are not used alone as proof of state. All three desktop
windows closed normally with exit 0. All seven task Host/provider/window PIDs are
gone and the hidden workspace is stopped. Cleanup and readbacks are retained.
